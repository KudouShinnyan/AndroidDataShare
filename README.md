# AndroidDataShare

[简体中文](README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md) · [日本語](README.ja.md)

主应用已经下好资源包时，让同一游戏的不同服（不同包名）、跨用户安装或容器分身共用一份静态数据，不必再下一遍，或省下几 GB 占用。

## 前提

本应用只是配置工具，执行共享至少需要 Shizuku 授权；纯 Shizuku 只能复制，且一般仅限主用户的公共存储路径，少数被设为私有权限的目录仍会失败；Sui / root 还能硬链接和挂载。Releases 只发布一个 APK。开机恢复模块按需生成、手动刷入一次，仅用于挂载组的重启恢复；硬链接与复制落盘，重启后天然保留，不依赖模块。版本变化由本应用比对基线。

## 使用

装好 APK → 在主界面「执行权限」选后端并点「请求权限」→ 新建组、选主应用与共享目录、添加目标 → 保存即应用。未授权时配置与保存不可用，避免配置了却无法生效。共享方式按实际情况选硬链接 / 复制 / 挂载，组内可随时切换，删除组会一并撤销共享。

挂载组需要重启后自动恢复时，点主界面的生成按钮，把得到的 zip 在 Magisk / KernelSU / APatch 里从本地安装；不刷模块也能正常使用，硬链接与复制组无需这一步；只是挂载组重启后需打开本应用补挂一次。

Download/AndroidDataShare/ 下有三份可自行补充的文件：containers.txt 记容器包名和目标应用的数据路径，sync_groups.txt 记可共用的一组服，desync_groups.txt 记需避开的一组服。自己加，或交给我加进源码；内置那份和这里补的都会读。格式见文件开头的注释。

## 注意

- 两端资源版本与更新进度要一致。若不同步，三档都无法对齐，请不建立共享、让两端各自下载与更新。
- 硬链接只占一份空间，主应用更新后不会跟过来，点「重新共享」重建；复制是独立副本，多占一份空间，同样不跟更新；挂载的目录内文件会自动跟随，但不一定按预期生效，是否生效以目标应用身份实读为准。
- 挂载在更旧的系统上说不定还有效，具体是哪个版本已经记不清了。本来以为新系统里挂载不按预期时，硬链接就是最优解了。Android 15 上好像成了，没想到同一台设备到 Android 17 又链不上。这软件好像一下没了大半意义，只能尽量多塞点提示了。
- 部分设备与系统组合尚未逐一验证；联网游戏的反作弊与账号风险由使用者自行承担，重要数据请先在本机确认。
